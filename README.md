# STM32 OTA Bootloader 升级项目

这是一个基于 STM32F103 的 OTA/IAP 升级项目，用于实现应用程序的远程传输、外部 Flash 缓存、Bootloader 校验写入和 App 跳转。项目面向嵌入式岗位面试展示，重点体现对 Bootloader、Flash 分区、通信协议、状态机和 HAL 外设驱动的综合实践能力。

## 项目目标

项目模拟真实嵌入式设备的固件升级流程：上位机节点发送升级指令和新固件数据，目标设备接收固件后先缓存到外部 W25Q32 Flash，再由 Bootloader 校验元数据和程序入口，最后写入片内 Flash 的应用区并跳转运行。

该项目不是单一的点灯 Demo，而是围绕“设备如何安全升级应用程序”搭建的一套完整验证工程。

## 核心功能

- Bootloader 启动后读取 W24C02 中的升级标志位，判断是否进入升级流程。
- 使用 W25Q32 外部 Flash 保存待升级 App 的元数据和固件内容。
- Bootloader 校验 App 栈顶地址、复位入口地址和程序大小后，再擦写片内 Flash。
- 支持从 Bootloader 跳转到应用区运行，并在跳转前关闭中断、关闭 SysTick、重定位中断向量表。
- 使用 LLCC68 LoRa 模块进行固件数据传输，支持按 100 字节分包发送。
- 使用 CRC 外设计算应用程序校验值，用于升级数据完整性验证。
- 保留 CAN 通信接口代码，便于扩展为 CAN 升级链路。
- 提供旧版本 App 和新版本 App，通过 LED 常亮/闪烁验证升级效果。

## 工程目录

| 目录 | 说明 |
| --- | --- |
| `P00_getway_led1_hal` | 上位机/发送端工程，负责发送升级命令和 App 数据，集成 LLCC68 LoRa 驱动 |
| `P01_led1` | 旧版本应用程序，作为升级前运行的 App，现象为 LED 常亮 |
| `P01_led2` | 新版本应用程序，作为升级后的 App，现象为 LED 闪烁 |
| `P02_bootloader_hal` | Bootloader 主工程，负责升级判断、Flash 擦写、App 校验与跳转 |
| `P03_bootloader_reset_hal` | 备份/恢复区工程，用于恢复默认程序或异常回退验证 |
| `bin` | 存放生成的固件二进制文件 |
| `测试代码` | 测试和过程验证代码 |

## Flash 分区设计

| 区域 | 地址范围 | 用途 |
| --- | --- | --- |
| B 区 Bootloader | `0x08000000 - 0x08004000` | 启动、升级判断、写入 App、跳转 App |
| 备份区 | `0x08004000 - 0x08008000` | 默认/恢复程序存放区 |
| A 区 App | `0x08008000` 起 | 用户应用程序运行区 |

外部 W25Q32 Flash 的第一个扇区用于保存升级元数据，后续空间用于保存待升级固件。元数据主要包括 App 在外部 Flash 中的起始地址和 App 大小。

## OTA 升级流程

1. 目标设备启动后进入 Bootloader。
2. Bootloader 从 W24C02 指定地址读取升级状态和校验密钥。
3. 如果检测到升级标志，Bootloader 从 W25Q32 读取 App 元数据。
4. Bootloader 校验 App 大小、栈顶地址和复位中断入口地址。
5. 校验通过后擦除片内 Flash 的 App 区。
6. Bootloader 按页读取 W25Q32 中的固件数据，并以半字方式写入片内 Flash。
7. 写入完成后清除升级标志。
8. Bootloader 设置 MSP、重定位 VTOR，然后跳转到 App 复位入口运行。

## 通信与数据传输

上位机工程通过 LLCC68 LoRa 模块发送升级命令和固件数据。发送端收到升级命令 `ZGF` 后进入发送状态，从 App 起始地址读取固件内容，并按固定长度分包发送。

为了保证传输稳定性，发送端每包发送 100 字节，并在包间加入延时。固件发送完成后，使用 STM32 CRC 外设计算 App 区 CRC 值，并把 CRC 结果发送给接收端用于完整性校验。

## Bootloader 关键实现

- 升级状态管理：使用 W24C02 保存升级标志，掉电后仍能保留升级状态。
- 外部缓存机制：使用 W25Q32 存放待更新固件，避免边收边写片内 Flash 带来的风险。
- App 合法性校验：检查栈顶地址是否位于 SRAM 范围，检查复位入口是否落在 App 地址区间。
- Flash 写入：擦除 App 区后，以 `FLASH_TYPEPROGRAM_HALFWORD` 方式写入程序数据。
- App 跳转：跳转前关闭相关中断和 SysTick，设置 MSP，更新 `SCB->VTOR`，再调用 App 复位函数。

## 面试可讲点

- 解释 Bootloader 和 App 为什么需要分区，以及中断向量表为什么要重定位。
- 说明 OTA 升级中“先缓存到外部 Flash，再写入片内 Flash”的可靠性优势。
- 说明如何判断一个 App 镜像是否合法：栈顶地址、复位入口地址、程序大小、CRC 校验。
- 说明升级标志为什么放在 EEPROM/W24C02 中，而不是只放在 RAM 中。
- 说明 LoRa 分包传输时如何处理包大小、延时、完整性校验和状态切换。
- 说明 CAN 接口如何扩展为另一条固件升级链路。
- 说明从 Bootloader 跳转到 App 前需要关闭中断、关闭 SysTick、设置 MSP 和 VTOR 的原因。

## 开发环境

- MCU：STM32F103 系列
- 开发框架：STM32CubeMX + STM32 HAL
- IDE：Keil MDK-ARM
- 主要外设：GPIO、USART、SPI、I2C、CRC、CAN
- 外部器件：W25Q32 Flash、W24C02 EEPROM、LLCC68 LoRa 模块

## 验证方式

- 将 `P02_bootloader_hal` 烧录到 `0x08000000 - 0x08004000`。
- 将 `P03_bootloader_reset_hal` 烧录到 `0x08004000 - 0x08008000`。
- 将 `P01_led1` 作为旧版本 App，用于验证升级前 LED 常亮效果。
- 将 `P01_led2` 作为新版本 App，用于验证升级后 LED 闪烁效果。
- 使用 `P00_getway_led1_hal` 作为发送端，触发升级并发送新固件。

## 项目价值

通过该项目可以展示嵌入式开发中从外设驱动到系统启动流程的完整能力，包括 STM32 HAL 驱动使用、片内 Flash 擦写、外部存储管理、Bootloader 跳转、无线通信传输、CRC 校验和状态机设计。该项目适合作为嵌入式软件、单片机开发、物联网终端开发等岗位的面试作品。
